# Jellytool 使用说明

适用：Apple Silicon macOS 开发包。Jellytool 使用独立的数据目录和本地端口 3435，
通过 Jellytoken 为本机 Agent 提供模型。首次打开不需要另装插件。

## 供应商页：从 Key 到可用模型

1. 到“快速上手”的“供应商接入”，点击“创建 Jellytoken API Key”，前往
   https://www.jellytoken.com/api-keys 新建并复制 Key。回到应用粘贴，点击“验证并接入”。
   已有 Key 可以直接填写。验证失败时不会替换已保存的 Key。
2. 点击“选择模型”，在快速上手第 2 步展开三类推荐：解决复杂问题、日常工作与编码、
   简单任务。每张卡片显示模型名称、简短用途和右上角勾选框；点击卡片选择或取消。
   GPT 默认固定展示并标记“推荐”：gpt-6-astra 用于解决复杂问题，gpt-6.1-sol 用于日常工作与编码，
   gpt-6.1-terra 和 gpt-6-luna 用于简单任务。没有权限的型号仍会显示，点击时提示先在 Jellytoken 开通模型权限；
   权限只以当前 Key 的接口模型目录为准，不以历史选择判断。分类按钮统一显示“全选可用模型”，
   选中全部可用型号后显示“清空”；跳过无权限型号时会提示。目录读取失败时提示刷新重试。
   其他系列在每档保留一个代表，MiniMax 不再出现在推荐中，
   已选的 MiniMax 模型保留，也可从完整目录选择。
   分类标题旁的按钮统一显示“全选可用模型”；选中全部可用型号后显示“清空”，清空后切回“全选可用模型”。
   全选会保留其他选择并去重，清空仅清除该分类，
   不影响其他分类或从完整目录选用的模型。
   展开后入口变成“收起模型”；收起保留未保存的选择，再次点击“选择模型”可继续编辑。
3. 顶部“推荐 / 已选”切换共用同一选集。“已选”包含从完整目录补选的模型，也可以取消勾选。
   点击底部“查看更多模型”进入供应商的完整模型目录，当前未保存的选择会一起带入。
   “返回推荐”保留目录内的调整，再次进入目录仍是同一选集。
4. 点击“保存选择”统一保存。完整目录从快速上手打开时，保存后返回快速上手；
   直接从供应商页打开时，保存后留在供应商页。取消会放弃本次调整，恢复进入前的已保存选择。
   没选任何模型就不会提供模型，不会自动选择整个目录。
   更换 Key、Base URL 或协议请使用第 1 步的“连接设置”或供应商的常规编辑器。
   检测使用当前填写的草稿，不会保存；“采用”只修改草稿，点击“保存”后才生效。
   Key 留空保留原 Key。目录验证成功后，新的连接设置和 Key 才会一起保存。
   新连接及“恢复默认”使用 Responses 协议；已有手动选择的协议保留。
   WorkBuddy 5.9.3 接入 Responses 上游模型时，会同时写入 Responses 客户端标记和 `/v1/responses` 地址。
   OpenCode 会按模型选择 Responses，只有 Chat 或协议未知的模型保留 Chat。
   Pencil、ZCode 新接入且所选模型全部支持原生 Responses 时默认选 Responses，已有手动设置保留。
   Claude Code、Gemini CLI 等使用各自固定协议，由网关完成必要转换。
5. “重新获取模型”会重新读取当前 Key 的目录。若读取失败，先核对 Key、账号权限
   和网络；模型出现在目录里不代表已经验证价格、协议或工具调用兼容性。
   目录中的输出类型不代表对应协议和工具调用已经验收。

供应商保存只更新选集，不会自动连接或改写任何 Agent 配置。
供应商关闭后不会向它转发请求，Key 和选集会保留，重新打开后可继续使用。

## 快速上手第 4 步：在 Agent 中使用

前三步完成供应商接入、模型选择和 Agent 接入后，第 4 步会按 Agent 展示使用说明。
只展示前面已接入的 Agent，通过 Tab 切换查看对应说明；尚未接入时会提示先完成第 3 步。
断开接入后，对应的 Tab 会移除。它是可随时查阅的指南，顶部进度
单独统计前三项配置；查看说明不会发送模型请求或改动 Agent 配置。

- Claude Code：输入 `/model` 切换 Opus、Sonnet 或 Haiku 档位；每个档位背后的实际模型
  在 Jellytool 的 Agent 页设置。
- Codex CLI：输入 `/model`，选择 Jellytool 提供的模型。Codex 桌面应用或 IDE 扩展
  使用对话中的模型选择器。
- OpenCode：输入 `/models` 选择模型。
- Pi：输入 `/model` 选择模型。
- Gemini CLI：先在 Jellytool 的 Agent 页选好启动模型，再启动新的 Gemini CLI 会话。
- WorkBuddy、VS Code 及使用图形模型菜单的 Agent：在对话窗口的模型选择器中选模型。

接入后按 Agent 页的提示重新打开工具，让配置生效，再新建会话并发送简短消息。
使用期间保持 Jellytool 运行。找不到模型时，展开第 4 步的排查说明，确认供应商已
登录并启用、模型已勾选并保存，以及当前 Agent 已接入且模型列表包含目标模型。

命令参考：[Claude Code](https://code.claude.com/docs/en/model-config)、
[Codex CLI](https://learn.chatgpt.com/docs/models?surface=cli)、
[OpenCode](https://opencode.ai/docs/models)。Jellytool 特有的接入和档位映射以 Agent 页为准。

## 快速上手第 5 步：图片生成配置（可选）

如果需要替换 Agent 使用的生图模型，可以在这里配置；不需要生图时可以跳过，
它不计入顶部的三项必需配置。

1. 点击“选择生图模型”，到“设置 → 模型 → 生图模型”选择模型。
   当前为“关闭”时，选择模型即可启用。之后调用图片工具时，未指定型号就会使用这里的默认模型。
2. Jellytool 默认安装 `jellytool-image`。点击“检查图片工具”查看实际状态。
   如果资源库已关闭，先点“启用资源库”；如果尚未安装，点击“安装并配置图片工具”，
   在工具卡片选择需要的 Agent，再点击“添加到资源库”。已安装时点击“配置图片工具到 Agent”，
   在“资源库 → MCP 服务器”的工具行勾选 Agent。已有的兼容 `magpie-image` 会保留，
   不需要重复安装；仅在 Agent 中发现的条目可以先导入资源库。读取或配置失败时，按错误提示重试。
3. 重新打开 Agent 或新建会话，在 Agent 自己的 MCP 设置中确认工具已启用。
   WorkBuddy 需要在其 MCP 设置中手动打开一次。

   如果只想让本次请求使用指定生图模型，可以直接在提示词中写明，例如“使用
   gpt-image-2.5-flare 模型生成图片”。Agent 会把型号传给 `generate_image`，
   仅本次调用生效，不会修改“设置”中保存的默认模型。该模型需要已在 Jellytool
   中配置并可用；不指定型号时使用已保存的默认模型。

   指定尺寸时，让 Agent 调用 `generate_image` 并传入 `size`：可以使用宽高比
   （如 `1:1`、`16:9`、`9:16`），或以“宽x高”表示像素尺寸
   （如 `1024x1024`、`1536x1024`、`1024x1536`，使用英文小写 `x`）。
   宽高比只决定画面比例，不保证具体像素分辨率；可用尺寸以所选模型为准，
   不指定 `size` 时使用模型默认值。然后可以直接对 Agent 说：

   > 请使用 jellytool-image MCP 生成一张 16:9 的海滨城市日落插画，保存到 assets/seaside.png。

   或明确指定像素分辨率：

   > 请使用 jellytool-image MCP 生成海滨城市日落插画，设置 size 为 "1536x1024"（宽 1536 像素、高 1024 像素），保存到 assets/seaside.png。

   或同时指定模型和比例：

   > 请使用 jellytool-image MCP，使用 gpt-image-2.5-flare 模型生成一张海滨城市日落插画，size 设置为 "16:9"，保存到 assets/seaside.png。

   示例旁的复制按钮可以复制整段提示词；如果沿用 `magpie-image`，在提示词中使用该名称。
   Agent 会调用 `generate_image`，图片保存到项目中。修改已有图片时，提供原图路径和修改要求。
   如果工具先返回任务 ID，让 Agent 使用该 ID 调用 `generation_result` 等待结果，
   无需重复生成。使用期间保持 Jellytool 运行。

## WorkBuddy：连接与实际选模

1. 先退出 WorkBuddy，备份它实际使用的 models.json 和已有 magpie 配置。
   国内版默认文件是 ~/.workbuddy/models.json；设置了 WORKBUDDY_CONFIG_DIR 时
   以该目录为准。
2. 到 Jellytool 的 Agent 页连接 WorkBuddy。已有 magpie 和其他供应商模型会保留。
   Jellytool 条目使用自己的 vendor（jellytool）、本地地址和接入标识。
3. 打开 WorkBuddy，在它自己的模型选择器中选模型并发送一条简短消息。
   真实请求会使用你的账号额度；模型列表不代表请求或工具调用已经验收。
4. 在 Jellytool 的 Agent 页调整 WorkBuddy 模型列表，会显式同步已连接的 WorkBuddy。
   必要时退出并重新打开 WorkBuddy，以便它读取新列表。
   只保存供应商选集不会写 WorkBuddy；可调整 Agent 模型列表，或断开后重新连接。
5. 如果完整模型 ID 已属于其他供应商，连接会被拒绝。请从 Jellytool 的选集中移除
   冲突 ID，避免相同 ID 同时代表两个供应商。

## 断开、恢复和 magpie 共存

先退出 WorkBuddy，在 Agent 页预览断开，再断开。Jellytool 只移除自己添加的条目。
若没有其他变更，原文件恢复到原始内容；连接期间对其他条目的修改会保留。
原来不存在的文件，仅在没有其他数据时删除。恢复失败会保留自动快照：
不要删除 Jellytool 的数据，解决权限等提示问题后重试断开。

首次共存验收建议先退出 magpie，完成一轮连接、选模、断开后，再打开 magpie 检查
原有接入，最后检查两个应用同时运行的情况。保留人工备份到全部验收结束。
文件层面的保留测试不代表运行中的两个程序不会竞争写同一文件。

## 状态栏与退出

顶部状态栏显示 Jellytoken 图标。点击图标，在菜单里选择“打开 Jellytool”或
“退出 Jellytool”。关闭主窗口后，Jellytool 会继续运行并为已连接的 Agent 转发请求。
可以通过状态栏菜单或 Dock 图标重新打开窗口。
退出 Jellytool 后本地转发停止；需要直连或切回原接入时，先从 Agent 页断开。

## 常见问题

- 没有模型：检查 Key 和权限，重新获取模型，再查看“全部模型”。
- 保存后 WorkBuddy 没变化：供应商保存与 Agent 连接是两步；在 Agent 页调整列表，
  并退出重开 WorkBuddy。
- 无法连接或模型 ID 冲突：保留原文件，移除冲突选项后重试，不要手动删除其他供应商。
- 3435 端口被占用：确认是不是另一份 Jellytool，先由你决定退出哪个应用；程序不会抢占端口。
- 恢复失败：保留原文件、备份和 Jellytool 数据，记录完整错误后重试。
- 状态栏空间不足：检查 macOS 的隐藏图标管理器；Dock 中仍可打开主窗口。

开发包尚未正式签名或公证。其他 Agent、真实模型工具兼容性和各平台运行情况仍需人工验收。
反馈请附系统、WorkBuddy 版本、完整模型 ID 和错误原文，隐去 Key。

## 修改模型推荐配置

配置位于 Jellytool 数据目录的 `model-recommendations.json`，通常为
`~/.config/jellytool/model-recommendations.json`。首次启动会创建文件，更新程序不会覆盖它。
修改后刷新页面或重启 Jellytool 生效。JSON 写错时，推荐区域会报错，原文件会保留。

- `tiers.complex`：解决复杂问题；`tiers.daily`：日常工作与编码；`tiers.simple`：简单任务。
- 每个数组按显示顺序列出模型。`id` 必须与接口中的完整型号一致。
- `recommended: true` 显示“★ 推荐”；`alwaysShow: true` 在没有权限时仍展示卡片，点击时提示开通权限。
- 可加 `name` 自定义显示名；移动条目到另一个档位可调整分档，删除条目可取消推荐。
- 将某档设为 `[]` 可隐藏该档模型；删除该档位字段则恢复自动计算。配置不改变接口权限和已保存选集。

## 检查 Jellytool 更新

Jellytool 启动后检查新版，默认每 24 小时再检查一次。你也可以在“设置 → 关于”
点击“检查”。发现新版后，顶部会显示“下载更新”；点击可查看更新说明，再打开
浏览器下载并手动安装。点提示旁的关闭按钮可跳过该版本，新版发布后会重新提示。
“设置 → 关于”可以关闭自动检查，或重新显示已隐藏的提示。

尚未接入发布地址的开发包会显示“此构建尚未配置更新检查”。Jellytool 只检查
自己的版本，不使用 magpie 的更新包。
